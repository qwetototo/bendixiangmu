# 人员设备中心数据库变更记录

## 2026-08-06 — 设备定位坐标跟随自定义地图

- 设备定位坐标变换从写死常量改为从当前激活地图的 metadata 派生：偏移量绑定地图
  `positioningOrigin`（预览中点选的定位原点），比例随 `scaleRatio` 线性推导。
- 默认地图（`scaleRatio=100`、定位原点未配置）派生结果与原常量一致，行为不变；
  已保存的旧地图未配置定位原点时自动回退默认偏移。
- 实时位姿、轨迹路径与历史回放共用同一变换，自定义地图在预览中设置定位原点后
  设备点即可与地图对齐。

## 2026-08-05 — 实时监控性能优化

- 实时区域统计与 ECharts 更新限制为每 750ms 一次，同一设备一帧内只渲染最新定位。
- 设备筛选列表只在设备首次出现或离线时更新，不再随每条定位消息重复计算。
- 实时轨迹使用可复用动态缓冲区增量写入，不再为每个定位点销毁并创建几何体。
- 设备达到 12/20/24/30 台时分级调整像素比、阴影和实时轨迹；进入回放后恢复完整回放效果。
- 实时与回放定位点均不再创建方向箭头；`theta` 仍保留在数据协议中，但不再参与标记渲染。

## 2026-08-05 — 登录安全与用户管理

- 新增 `app_user` 登录用户表，密码仅保存 BCrypt 摘要，用户等级 `0` 为管理员、`1` 为普通用户。
- 新增 JWT 登录校验；管理员可调用所有业务接口，普通用户仅允许查询。
- 配置中心新增管理员专用用户管理，可创建、修改、删除用户并设置新密码；新用户默认
  密码为 `deepfusionrobotics`，默认密码和后续修改的密码都只在 BCrypt 处理后入库。
- 每个楼层继续保留自己的模型列表和模型路径；模型变换参数、比例与定位原点改为建筑级
  配置，切换、新增或保存楼层时会同步参数，但不会覆盖楼层的模型选择。
- 生产部署必须通过 HTTPS 保护登录密码和 JWT 的传输。

## 2026-07-31 — 2.0.2 未知设备自动注册

- 轨迹批量写入前可自动注册 `device` 表中不存在的设备编号。
- 自动注册与轨迹写入位于同一事务，注册失败时不会产生半完成数据。
- 使用 `ON CONFLICT (device_id) DO NOTHING` 处理并发首次上报。
- 自动注册设备默认未绑定人员，电量为 `80`，状态为 `online`。
- 配置项 `dfmotion.trajectory.auto-register-unknown-devices` 控制是否启用，当前默认
  为 `true`；关闭后未知设备轨迹仍由外键拒绝。

## 2026-07-31 — 2.0.1 设备编号口径调整

- 定位设备和信标的唯一编号不再限定为 MAC 地址格式。
- 定位设备编号可直接使用上报数据中的 IMEI、序列号或纯数字业务编号，例如
  `860000000000022`。
- 数据库字段仍为 `VARCHAR(64)` 且保持唯一约束，不需要迁移表结构。
- 前端 CSV 导入兼容旧“MAC地址”表头，新导出文件使用“设备编号”或“信标编号”。

## 2026-07-31 — 2.0.0 全量重建

`docs/init_postgresql.sql` 已由“增量兼容初始化”改为“删除并重新创建 `dfmotion` 数据库”的全量部署脚本。

### 主要变化

- 删除 `person_device_binding`，当前绑定改为 `device.personnel_id`。
- 删除人员角色、电话、邮箱、在职状态和备注。
- 删除定位设备类型、协议、固件、最后上报时间和备注。
- 删除信标型号、固件、协议、区域、校准时间和备注。
- 删除管理表中当前业务未使用的创建/更新时间字段。
- 删除轨迹表未被 `TrajectoryMapper` 使用的扩展字段。
- 删除所有演示数据和旧数据库增量迁移语句。
- 信标补齐 `x/y/z` 三维坐标。
- 设备和信标电量默认值统一为 `80`。
- 设备状态限定为 `online/offline/SOS`。
- 增加数据库 SOS 触发器，在状态进入 SOS 时自动创建 `alert_event`。
- 保留后端仍在使用的 `alert` 兼容视图，并增加写入转发触发器。
- 轨迹分区改为根据执行日期自动创建当前月与下个月，不再写死月份。

### 破坏性影响

执行脚本会永久删除现有 `dfmotion` 数据库。执行前必须备份并停止所有连接数据库的服务。

后端管理接口已同步到 2.0.0 数据库结构：管理查询不再依赖
`person_device_binding`，人员与设备通过 `device.personnel_id` 直接关联，并已补齐部门、
人员、定位设备、信标设备、告警及首页汇总接口。部署时必须同时发布本次后端代码与
`init_postgresql.sql`，不能将新版数据库与旧版后端混用。

### 部署命令

```bash
pg_dump -h <数据库主机> -U <数据库用户> -Fc \
  -d dfmotion -f dfmotion_before_rebuild.dump

psql -h <数据库主机> -U <数据库所有者或超级用户> \
  -d postgres -f docs/init_postgresql.sql
```

执行账号必须是 `dfmotion` 数据库所有者或 PostgreSQL 超级用户，并具备终止连接与重新建库权限。
